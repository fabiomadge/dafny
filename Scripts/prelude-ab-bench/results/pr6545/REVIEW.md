# Review of dafny-lang/dafny#6545, "fix: remove the unguarded $Box($Unbox(x): T) == x axiom"

PR head `21cd226c0` (five commits, Ernie Cohen), base `5f717bf44` = current `master` (unchanged on
2026-10-02). No reviews or comments on GitHub; all five commit messages read. Evidence below was
produced on Linux arm64 with Z3 4.16.0, a Debug build of `master` and of the PR head, and Dafny 4.11.0
from NuGet, unless it says Z3 5.1.0.

## Verdict

Merge it, after three changes: lead the description and the regression test with a Dafny program
that proves `false` through the deleted axiom (one exists, below; the issue and the PR say none is
known), cut the comments and the description to what is essential, and move the thirteen proof
stabilizations into a PR of their own that lands first. As submitted they hold in CI's order but not
across orders; a version that holds at every seed I tried is prototyped (see the benchmark). The fix
itself is right, minimal and self-contained, and it makes proofs cheaper: -4.3% per program over
1,249 programs.

## What it does, and should it be done

The prelude axiom `forall<T> x: Box :: $Box($Unbox(x): T) == x` says that every box is the box of a
value of every type `T`. At `bool` that makes every box `$Box(true)` or `$Box(false)`, while
`$Unbox($Box(x)) == x` makes `$Box` injective at `int`: no model. The PR deletes it, adds the guarded
inverse for the two built-in types that had none (`ORDINAL`, `Field`), and makes the type axiom of a
heap field also say `$IsBox(h[o, f], T)`, so that the per-type guarded inverse gives
`$Box($Unbox(h[o, f])) == h[o, f]`, which `CondApplyBox` relies on when it translates
`$Box($Unbox(E))` as `E`.

It should be done, and it is a reachable soundness fix, not only axiom hygiene. Values of a generic
datatype at different type arguments share Boogie's `DatatypeType`, so a quantifier over `Opt<bool>`
can be instantiated at `Opt<int>` values, which unboxes their contents as `bool`s; with the deleted
axiom, three such ints collapse into two bools. This verifies ("3 verified, 0 errors") on `master`,
with either resolver and, at the default options, for `/randomSeed` 0 to 2, and on 4.11.0 at the
default options; it is refused with the PR:

```dafny
datatype Opt<T> = None | Some(v: T)

function F(b: bool): int { if b then 1 else 0 }

lemma Bad(x: Opt<int>, y: Opt<int>, z: Opt<int>)
  requires x == Some(0) && y == Some(1) && z == Some(2)
  requires forall o: Opt<bool> :: o.Some? ==> F(o.v) <= 1
  ensures false
{
  assert x.v == 0 && y.v == 1 && z.v == 2;
}

lemma Contradiction()
  ensures false
{
  Bad(Some(0), Some(1), Some(2));
}
```

The deleted axiom is the cause: `master`'s binary with `master`'s prelude minus that one line refuses
`Bad`, as does `master`'s binary with the PR's prelude; the PR's binary with `master`'s prelude
(part 3 alone) still proves `false`; all seven of the author's open PRs merged together refuse it.
The two shortcuts I tried do not reach it even on `master`: the quantifier asserted in the body with
literal `Some(0)`, or a tautological body (`o.v || !o.v`), which Z3 simplifies away.

## Is this the right design

Yes. There is no sound unguarded form of the identity: it is false in the intended model, where a
box holds a value of one type. The guarded form already exists for every type a box can hold: in the
prelude for `int`, `real`, `bool`, `char`, `bv0`, `set`, `iset`, `multiset`, `seq`, `map`, `imap`;
generated by `AddBoxUnboxAxiom` for every type constructor not modeled as a box (classes, traits,
datatypes, newtypes, subset types, arrow types) and for bitvector widths above 0; and generated for
`fp32` and `fp64` in `EnsureFp32TypeConstantExists`/`EnsureFp64TypeConstantExists`. Guarding the
polymorphic axiom itself by `$IsBox` is not expressible (it has no `Ty` for a Boogie type `T`).

Part 3 is the minimal way to keep `CondApplyBox`'s rewrite justified at heap reads, which is where the
translator relied on the identity without an `$IsBox` fact (the issue reports that with parts 1 and 2
alone the lost proofs are heap programs; I did not re-run that sweep, but the regression test's two
constructors fail exactly so). Sequence, map, array, datatype-field
and function-result boxes get their `$IsBox` from their container's or function's type. The alternative, not collapsing
`$Box($Unbox(read(..)))` at heap reads, would add terms to every query that reads a field, for no
gain in soundness; I did not prototype it. I checked the generated type axioms: the conjunct appears
for mutable, ghost and trait fields of type `int`, `bool`, `seq<T>`, arrow and `bv8`, and for fields of
generic classes; fields of a type parameter (`$IsBox` already), array and `array2` elements (`$IsBox`
already), `const` fields (functions, not heap reads) and `ORDINAL` fields need none. `ORDINAL` is a
Boogie synonym of `Box` and its fields are read and written unboxed (`read($Heap, d, D.go) == o`).

Two small points:

- The new `TORDINAL` inverse is needed, and it adds a proof. `ORDINAL` is rejected only as the type
  argument of a generic call (`Id(o)`); `set<ORDINAL>` boxes ordinals. This lemma fails on `master`
  and verifies with the PR, at seeds 0 to 2 with either resolver, and fails again with only that
  axiom removed (checked 2026-10-06). It deserves a test:

  ```dafny
  lemma Subset(s: set<ORDINAL>, t: set<ORDINAL>)
    requires forall o :: o in s ==> o in t
    ensures s <= t
  { }
  ```

  For the `TField` inverse I found no program that needs it. The analogous `set<field>` lemma (with
  `--referrers`) crashes the translator on `master` and with the PR alike, because `TrType` has no case
  for `FieldType`; that is a separate, pre-existing bug.
- `AddInstanceFieldAllocationAxioms`'s doc comment still says the type axiom concludes
  `$Is(h[o, f], TT(PP))`; it should mention the new conjunct, and that is the place for the reason
  (prototyped).

## Scope

The fix is self-contained. What it lacks is a test that fails without it: `git-issue-6534.dfy` passes
on `master` too (its constructors need part 3 only because parts 1 and 2 remove the identity; with
parts 1 and 2 alone both fail, as the commit says). The program above, as `Bad`, fails on `master`
and passes with the fix (prototyped).

The other four commits do not belong to the fix:

- **Thirteen proof stabilizations** (eight in the standard library, five integration tests). They are
  improvements on `master` as well (below), and they touch files that other open PRs touch: nine other
  open PRs rebuild `binaries/DafnyStandardLibraries.doo`; #6431 also edits
  `DivMod.LemmaMultiplyDivideLt`'s proof, which this PR rewrites; #4596 stabilizes `Power2.Lemma2To64`
  differently. Landing them first, in their own PR, keeps this one to the axiom change, puts those
  conflicts where they belong, and lets the library's owners review the library edits. Squash-merging
  collapses the five commits into one, so the commit structure does not keep them apart.
- `server/counterexample_commandline.dfy`'s new expectation is part of the fix (its counterexample
  changes from `'\0'` to `'\U{0002}'`; both are counterexamples since `p[0] == '?'`).

## Benchmark (`Scripts/prelude-ab-bench`)

Release builds of `master` and of this PR, each with its own prelude, Z3 4.16.0, at Boogie seed 1,
where two runs of `master` give every VC the same resource count (Dafny's default seed, 0, does
not). The corpus is 2,077 programs: every lit and standard-library program, Kondo's and
DafnyBench's 41, and the 90 files of dafny-lang/libraries, all at `master`'s sources, so this
measures the fix without the stabilizations.

**The fix makes proofs cheaper.** It changes the cost of 27,050 of the 27,063 VCs. Over the 24,821
of them that are proofs, in 1,249 programs, it costs **-4.3% [-4.7, -4.0] per program** (each
program weighs the same; 95% bootstrap intervals that resample programs) and -2.0% [-2.6, -1.5] as
a geomean over VCs: lit -4.6% [-5.0, -4.3] (1,082 programs), dafny-lang/libraries -4.1%
[-6.8, -2.0], Kondo -1.3% [-2.0, -0.7], the standard library -0.9% [-2.5, +1.4], DafnyBench +0.7%
[-1.8, +4.9]. The total, carried
by a few heavy VCs, moves +3.5% [-11.8, +22.2]. Two runs of `master` differ by +0.0%. At seed 1, 23

### What was changed?

This verifies on master and 4.11.0, and is refused with this change:

`Opt<int>` and `Opt<bool>` values share a Boogie type, so the quantifier is
instantiated at `x`, `y` and `z`, which unboxes 0, 1 and 2 as bools. The
prelude axiom `forall<T> x: Box :: $Box($Unbox(x): T) == x` then makes their
